# 文档规范（Doc Conventions）

> 定位：公共文档，适用于任何项目，可提上游。

**先读全部 README**：开始工作前，阅读仓库的**全部** `README*` 说明——包括上游英文 `docs/README.md`、中文 `docs/README.zh_CN.md`，以及 fork 用户可能自行创建的根目录 `README.md` 或自定义 README。这些文件是重要的 AI 参考（含项目定位、硬件事实、使用约定等），AI 不应只依赖本文件。

**文档生成规范**：本仓库的说明文档（`AGENTS.md`、`CLAUDE.md`、`CHANGELOG.md`、`docs/**`、`assets/**`、`skills/**` 等）均为 AI 生成。请**勿手动输入或修改**这些文档内容——需要更新时，通过 AI agent 按本项目规范重新生成/改写，保持文档与代码、与约定一致；手动改动会造成不一致或被后续流程覆盖。例外：`docs/assets/` 是 fork 用户保存 README 补充文档与素材的目录，其内容由 fork 用户按 `docs/assets/readme.md` 约定管理，不属于上游同步的 AI 生成文档。

**文档分类规范**：文档分为两类，提交到上游的 PR 里**只允许包含公共文档**：

- **公共文档**：适用于**任何项目**的通用规范/约定（如 AI 工作流、commit 风格、文档生成规范、文档分类规范、目录骨架约定、CI/构建通用做法等）。这些**可以**提交到上游项目。
- **特定项目文档**：只适用于**本项目**的专属内容——指具体**功能实现、按钮设计、产品交互、专属业务逻辑**这类实现层面/产品设计细节。这些**不得**提交到上游项目。

判断原则：某段内容若属于本项目**功能/设计实现**（如某功能怎么实现、某按钮怎么设计、某交互怎么定义），即为特定项目文档，不提上游；而通用的 AI 工作流、文档规范、构建约定等，对任何项目成立，是公共文档，可提上游。

**中文写作规范**：编写或修改中文正文、占位文案、PR/MR 描述、issue 回复或文档说明时生效——中文正文内的逗号、分号和括号使用全角标点（`，`、`；`、`（`、`）`）。同一文件已有更统一的中文文案风格时，跟随该文件的既有风格。代码、命令、路径、URL、标识符、YAML/JSON 字段、正则、英文句子和必须机器解析的内容保持原样，不为了中文排版替换其中的 ASCII 标点。

**内容安全（凭证不入仓）**：凭证、令牌、密钥、授权文件和私钥**绝不写入仓库**或任何可能被 Git 跟踪的路径——没有例外。git history 是公开的，仓库可能被 fork、跨机器同步或被 agent 读取上下文，任何写进去的 token 都视同泄露。提交前用 `git diff` 扫描，看到形如 `glpat-`、`ghp_`、`sk-` 等敏感前缀立即终止，改用环境变量或系统钥匙串。误提交了敏感信息要立即私下报告，仅删除工作区文件不能保证 Git 历史中的秘密已失效。

**文件删除安全**：删除文件或目录时，移动到系统回收站 / Trash / Recycle Bin，不直接永久删除。不使用 `rm`、`rm -rf`、`find ... -delete`、`git clean -fd` 或等价永久删除命令处理工作区内容。macOS 优先用 Finder / AppleScript / `trash`；Windows 用 Recycle Bin；Linux 用 `gio trash`、`trash-put` 或桌面回收站。缺少可用回收站工具时先询问用户，不退化为永久删除。对 Git 引用类操作（如删除本地分支）先区分清楚：它不是文件系统删除；但删除 worktree 目录、未跟踪文件、生成物或临时 checkout 目录仍必须走回收站。
