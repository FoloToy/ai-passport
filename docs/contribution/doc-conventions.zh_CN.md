# 文档规范

本规范同时适用于人类贡献者和 AI Agent。每份文档只能维护 `docs/INDEX.md` 分配给它的事实。

## 语言与配对

- 每个维护中的 Markdown 默认路径 `name.md` 使用英文正文，并配对简体中文 `name.zh_CN.md`。
- 两个文件顶部提供互相切换链接，并在同一次变更中对齐标题层级、事实、命令、代码块、安全提示和本地链接目标。
- 翻译不改变含义时，命令、路径、URL、标识符和数据字段必须逐字节一致。
- 英文文件除语言切换标签 `简体中文` 外不得包含 CJK 正文。
- `python3 tools/check_repo.py` 会拒绝缺少配对、缺少语言链接、英文 CJK 正文、失效链接和强制 AI 路径结构漂移。

## 上下文与权威来源

- 每个任务从根目录 `AGENTS.md` 开始；任务路由表列出全部额外必读文档。
- `docs/README.md` 管理能力契约，`docs/hardware-design/specifications.md` 管理产品硬件，硬件指南管理工程约束与实机验收，`bsp_pins.h` 管理固件常量。
- 同一次变更更新权威文档和每个直接引用，不得为同一规则或硬件事实创建第二份叙述来源。
- 当前 checkout 必须自包含。维护中的说明不得依赖远程分支、社区归档、网站内容、私有文件或未跟踪本地配置。

## 放置位置

- 根目录 Markdown 只允许 `AGENTS.md`、`AGENTS.zh_CN.md`、`CLAUDE.md` 和 `CLAUDE.zh_CN.md`。
- 产品与工程文档放在 `docs/`；GitHub 识别的规范、模板、表单和 workflow 放在 `.github/`；自动化放在 `tools/`。
- 应用素材放在 `main/assets/`，且只有同一次变更至少加入一个被跟踪素材时才创建该目录。BSP 代码实际消费的可复用板级资源放在 `components/bsp`。
- 本固件基线禁止创建空目录、占位 README、应用归档、经验日志、品牌素材库、社区发布指南、fork 指南或项目运营 skill。
- 每份新增文档必须登记到 `docs/INDEX.md` 或所属目录索引；删除文档时必须移除全部入链。

## 写作与验证

- 写明准确触发条件、必须动作、禁止动作、输出、失败状态和验证命令。把“按需”“适用”“相关”等限定词替换为可测量条件。
- 未验证硬件结论必须标记为 `Unverified`，写明缺失测量，并禁止代码依赖。将其升级为产品事实前必须询问用户。
- 解释所有权、原因、失败方式和验收，不逐行复述源码。
- 只有发布维护者更新 `docs/CHANGELOG.md`，且只记录已经发布的上游基线行为或兼容性。
- 完成一组文档修改后运行 `./tools/validate.sh --static`。

## 安全与文件操作

- 文件、测试、示例、commit 和 PR 正文中禁止保存凭证、令牌、授权文件、私钥、个人数据、内部 endpoint、设备二维码秘密或未脱敏日志。
- 脱敏设备 URL 使用字面占位符：`https://example.invalid/?s=<secret>&k=<key>`。
- 保留已有用户修改和未跟踪文件。只删除用户明确授权或已接受任务范围要求删除的目标。
- 被跟踪文件可从 Git 历史恢复。删除分支、tag、远程引用或改写历史必须获得明确授权。
