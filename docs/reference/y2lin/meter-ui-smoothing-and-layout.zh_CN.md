# 音量计 UI：读数平滑、动画锚定与杂色块

**音量小哨兵** 计量页经历完整 UI 评审并发布社区后沉淀（对应提交 `8abb233`
及 `517c7c8` 至 `dec556e`）。这些经验适用于任何显示持续刷新读数或吉祥物式
角色的 AI Passport 应用。

## 用非对称 EMA 平滑实时读数

每 80 ms 采样一次的原始伪 SPL 值会让屏上的数字、进度条和分区色不停跳变，
读起来像噪声。在模型层用非对称 EMA 平滑——快攻（约 130 ms）让真实升高
立刻可见，慢放（约 0.5 s）让读数回落后趋于稳定而不是抖下去——Q8 定点实现，
首帧直通。凡是精度要紧的地方保留原始值：峰值/均值统计和告警状态机绝不能
滞后于现实。会话重置要保留平滑器，否则每次 OK 键重置读数都会闪一下零。
攻击/释放/收敛行为放在可主机测试的模型里——在那里测，别上设备测。

## 大数字要给固定宽度的盒子

28 pt 的读数若按自然宽度排布，一旦数值过 100 dB 多出第三位数字，就会撞上
dB 单位和状态徽章。把数字放进固定宽度盒子右对齐，刻度对齐面板边缘，位数
变化就永远不会挤动相邻元素。

## 动画锚定在创建位置，绝不锚定在当前位置

吉祥物一路越跳越高、最后冲出屏幕：浮动/跳跃动画用*当前* y 作为起始位置，
于是音量悬在分区边界附近时（动画不断重建），每次重建都把整个摆动窗口整体
上移。这类动画要从创建时记录的基础 y 出发；这样无论重建多频繁，摆动窗口
都恒定不变。

## 屏上杂色块有多个惯犯

同一个用户可见症状——一块意料之外的颜色块——在这一页上先后有四种不同根因。
逐一排查惯犯，不要猜：

- **被遗落的阴影。** `ui_pixel_panel_create()` 会创建两个兄弟对象：墨色投影
  和纸面本体；弹窗只隐藏本体，阴影就永远留在屏上。弹窗必须成对显隐——
  `ui_pixel_panel_create_ex()` 专门为此返回阴影。
- **低填充时的深色槽位。** 深石板色的进度条槽（0x2E3A44）在指示条很短时
  读起来就像一块游离的黑块；换成浅纸灰（0xE2E2D6）后，槽位在视觉上归回
  页面。
- **纯装饰。** 底部一条草地装饰在被移除前一直被当成意外色块；任何为了
  氛围加的超尺寸装饰都同理。
- **对象互相遮挡。** 吉祥物与统计面板重叠，把面板上一项统计值整个盖住。

## 开机白屏可能是 LVGL 池耗尽

计量页（约 90 个对象、LVGL 分配峰值约 35 KB）在构建到一半时耗尽了模板内置
的 24 KB LVGL 池：`lv_obj_create()` 返回 NULL，紧随其后的样式调用解引用了它，
而背光已经点亮、一帧都没渲染出来——表现为白屏，而不是崩溃报告。把 LVGL
切到 C 库分配器（`CONFIG_LV_USE_CLIB_MALLOC=y`），把静态池并入通用堆；同时
抬高构建页面和跑按键回调的任务栈——3584 字节默认值让 `app_main` 和
esp_timer 任务双双吃紧，8192 很宽裕。进入页面时记录构建后空闲堆，让现场
诊断成为可能。

## 对下一个应用的泛化

- 给人看的要平滑；给机器判定的一律用原始值。
- 任何位数可能变化的数字标签都用固定宽度容器。
- 每个动画对象一个创建时锚点；永远不要以当前位置为基准。
- 出现杂色块时，先枚举阴影、槽位、装饰和遮挡，再动代码。
- 白屏先怀疑“背光已亮的 NULL 对象崩溃”，再怀疑显示驱动；查 LVGL 分配器
  预算。
