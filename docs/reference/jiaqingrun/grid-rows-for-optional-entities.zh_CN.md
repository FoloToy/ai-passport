# 可能还不存在的实体，怎么给它们建网格行

为 **世界之尘** 加混血种族时记下的（AI Passport，`v0.49` → `v0.50`）。物种页从
六项变成十项网格：其中四项是混血，只有在两种基础部族接触之后才会存在。改完之后
一进物种页就重启——日志里没有警告，就是画网格的那一页上一个存储访问异常。这条
经验讲的是这个 bug 的形状，因为只要「用稠密 id 索引、但填充是稀疏的」，它就会
再出现一次。

## 前提

种族是一个稠密枚举，四支混血就是它的尾部：

```c
typedef enum {
    SP_HUMAN = 0, SP_BEAST, SP_BIRD, SP_SCALE, SP_INSECT, SP_WOOD, SP_BASE,
    SP_HY_HUMAN_BEAST = SP_BASE, SP_HY_BIRD_SCALE, SP_HY_BEAST_BIRD, SP_HY_WOOD_INSECT,
    SP_COUNT
} species_t;
```

网格是两列五行，位置由 id 直接推导：

```c
int col = s & 1, row = s / 2;
int x = 4 + col * 116, y = 4 + row * 30;
```

六个基础种族的格子在建页时一次建好。混血格子则在该混血**首次出现**时才建，
因为给一个并不存在的种族留一行，是玩家每次都要跳过的噪音。

## 这个 bug

刷新循环假设每个格子都存在，因为布局上确实有十个位置：

```c
label_set(s_sp_lbl[s], buf);                     /* s 是尚未出现的混血时为 NULL */
lv_obj_set_style_bg_color(s_sp_dot[s], ...);     /* NULL */
```

对于尚未出现的混血，`s_sp_dot[]`、`s_sp_lbl[]`、`s_sp_bar[]` 全是 NULL。而循环
又必须遍历这些 id——它得靠这个判断该不该显示——于是进入页面后的第一次刷新就
往空指针里写，板子重启。

有三点让这个 bug 比应有的更难找：

- 崩溃发生在**进入页面**时，而不是模拟过程中，所以看起来像建页 bug 而不是刷新 bug；
- 枚举 id 稠密且小，数组看起来是全覆盖的；
- 六个基础种族是好的，于是「网格能用」成了一个很自然的第一判断。

## 修掉它的那条规则

**只有创建路径可以碰格子。** 其余代码都在「格子已存在」之后运行，而「不存在」
用 `continue` 表达，而不是把 NULL 检查撒进每个绘制分支：

```c
bool show = (s < SP_BASE) || gp > 0.5f;   /* 基础种族永远有行 */
if (!s_sp_dot[s]) {
    if (!show) continue;                  /* 还没建：没有东西可画 */
    species_cell_create(s);               /* 数组的唯一写入点 */
}
/* 从这里往下，每个格子指针都是有效的 */
```

「隐藏」和「不存在」是两种状态。出现过又灭绝的混血会保留它的格子并隐藏，行位置
因此不会移动，玩家看着的时候布局不会重排。

## 选中也有同一个问题

方向键在同一段稠密 id 上移动选中项。如果它停在一个没有行的 id 上，高亮和详情页
就都指向了空。修法是让步进函数自己懂「存在」，并在当前种族消失时修正选中：

```c
static int species_step(int cur, int dir) {
    for (int k = 1; k <= SP_COUNT; k++) {
        int sp = (cur + dir * k + SP_COUNT * 2) % SP_COUNT;
        if (species_present(sp)) return sp;
    }
    return cur;                            /* 只剩一项：原地不动 */
}
...
if (!species_present(s_sp_sel)) s_sp_sel = 0;
```

让高亮位置直接由稠密 id 推导（`col = id & 1`、`row = id / 2`），而不是由「在可见
列表里的第几个」推导，是安全的关键：格子和高亮不可能对不上，因为两者都不是从
过滤后的列表算出来的。

## 可以带走的东西

1. **稠密 id 不代表格子数组稠密。** 只要「存在」是可选的，数组就是稀疏的，无论
   枚举长什么样。
2. **一个创建点，加上一道在使用之前就返回的守卫。** 把 NULL 检查抄进每个绘制分支
   是坏味道；一句 `if (!created) { if (!wanted) continue; create(); }` 才是那个
   不变量。
3. **不存在 ≠ 隐藏。** 首次出现时建、之后只隐藏，行位置才会在整个会话里稳定。
4. **不只守卫绘制，也要守卫选中。** 步进踩到不存在的条目是同一个 bug 的另一半，
   而它的表现是「详情页是空的」，不是崩溃。
5. **进入页面就重启，值得先在模拟暂停下复现。** 故障在页面的刷新路径上，暂停世界
   可以让实体集合保持不动，便于二分。
