# 无 FPU 掌机上的实时浮层、重绘与音频

同样整理自 **《世界之尘》** `v0.27`（社区 revision `5371`）。这个应用在 ESP32-C3 上
同时跑地图、四个页面、随机事件浮层和一个小音效引擎：无 FPU、无 PSRAM、240×320 屏幕。
有三类问题值得记录：一个让所有任务都饿死的全屏特效、一条既刺耳又卡顿的音频路径，
以及改文案后悄悄丢字的字库。

## 全屏不透明度动画 = 每帧一次全屏重绘

最初的神力特效把一层全屏颜色覆盖层在约 700 ms 内从全不透明淡到透明。预览里看很合理，
上机却是灾难：动画每一帧都让整屏失效，LVGL 任务整帧都在做混合，音频任务来不及补 I2S
DMA，于是特效和声音一起卡。

替代方案刻意做得很“无聊”：

- 显示一个静态浮层（或小横幅）来放结果文字；
- 固定显示约 4.5 秒，由主更新循环在到期时隐藏；
- 不暂停世界、不接管按键、不做透明度动画。

效果仍然清楚，但代价变成两次小范围失效，而不是几十次全屏重绘。如果确实想要全屏闪一下，
控制在一两帧；不要在这类硬件上做几百毫秒的逐帧动画。

两个配套习惯：

- 地图只在模拟 tick 变化或 dirty 标志置位时重绘，不要每次 UI 更新都重绘；
- 整个更新过程持有 LVGL 锁，并限制单次更新的工作量；开机和最大页面建好后打印
  LVGL 池与系统堆的水位。

## 音频路径：16 kHz、柔和波形、以及不被饿死的任务

第一版音效使用 22.05 kHz 方波，并放在低优先级任务里播放。在这块板子上，它既刺耳
（方波谐波）又不稳定（codec/I2S 路径按 16 kHz 配置，而任务在全屏重绘时抢不到 CPU）。
修法有四部分：

1. **16 kHz**，与 BSP 默认音频配置一致，而不是 22.05 kHz。
2. 音调使用**正弦 + 一个很轻的二次谐波**，而不是方波；火、洪水、轰鸣使用低通噪声；
   每个音效都加短起音和较长收尾包络，去掉爆音和尖锐边缘。
3. 由独立任务以**高于 LVGL 任务的优先级**（本构建为 6）写入 **1024 样本**的块，
   这样一次页面重绘不会把 DMA 饿死。
4. **幅度纪律**：合成峰值远低于满幅，并对保存的音量做上限（这里是 70），
   避免用户设置让每个提示音都变得刺耳。

六种神谕各自有一段短旋律（冰期下行清铃、洪水低涌、降福大调琶音等），而不是同一个
哔声换音高。同一个引擎还负责按键、确定、返回、休眠与唤醒，所以音频任务调用频繁；
把每个音效保持短、队列保持浅，可以避免延迟与重叠。

## 字库覆盖是构建产物，不是运行时的希望

界面语言是中文，字体是由源码字符串生成的 4 bpp 子集。几次发布加入新事件文案后，
纪年开始出现方块字：新字符从未进入字库。代码是对的，产物是旧的。

两个习惯可以避免复发：

- 任何改动文案的发布，都在构建固件前重新生成字库；
- 保留一个静态覆盖检查：扫描应用自己的字符串（以及生成器也会读的注释），与生成的
  cmap 比对。缺字应该让构建失败，而不是在设备上变成方块。

字体生成器还要对格式保持确定（LVGL 9、4 bpp、同样的行高）；生成字体与标签布局
不一致时，表现是裁切或行重叠，而不是报错。

## 顶部布局：不要把不相关的数字塞进同一个标签

顶栏最初把纪元、年份和人口放在一个 188 px 的标签里。人口到百万级时，文字在右侧被裁掉，
用户看到不完整的数字。拆成两个标签——左边纪元+年份，右边人口独立右对齐——并把速度
指示器改成小圆点，整类问题就消失了。检查时应该用最大可能的字符串（例如 `1.2万亿`），
而不是初始值。

通用规则：两个独立增长的数字，就给它们独立的标签和独立对齐。

## 结论

- 在这类硬件上不要做全屏不透明度动画；用带截止时间的静态浮层，并让世界继续运行。
- 按模拟变化重绘，而不是按比内容更快的定时器重绘。
- 16 kHz、柔和波形、包络和高优先级音频任务；块要大到能扛过一次重绘。
- 把字库当构建产物：随文案重新生成，并在构建里做缺字门禁。
- 独立增长的数字拆成独立标签，并用最大字符串测试，而不是最小字符串。
