# 240 × 320 掌机上的整屏旋转地图页

为 **世界之尘** 加第五页（整屏舆图）时记下的（AI Passport，`v0.46`／`v0.47`）。
板子是 ESP32-C3、8 MB Flash、无 PSRAM、240 × 320 竖屏、三个按键。两处问题表现
都像「设备卡死」：图片按 1:1 画在角落没旋转，以及切到这一页后按键全无响应直到
重启。凡是要做「一整页就是一张图」的页面，这两个坑都值得先知道。

## 转索引，不要转像素

世界地图由 UI 自己渲染进一块 208 × 126 的 RGB565 缓冲（52 KB，只有一块）。
整屏页要让它顺时针转 90°，再铺满整个屏幕。

省事的做法既不是再开一块缓冲做旋转，也不是调用旋转接口，而是让写入方和读取方
对内存布局的理解不一致：

```c
static inline int map_index(int x, int y) {
    return s_map_rot ? (x * MAP_H + (MAP_H - 1 - y)) : (y * MAP_W + x);
}
```

`s_map_rot` 置位后，每次落笔都按列优先写入，画完的缓冲按「宽 126、高 208」
描述给 LVGL，就已经是转好的：

```c
dsc.header.w = MAP_H;   /* 126 */
dsc.header.h = MAP_W;   /* 208 */
```

再让图片对象用 `LV_IMAGE_ALIGN_STRETCH` 拉到 240 × 320，并关掉抗锯齿。代价与收益：

- 不需要第二块缓冲、不需要旋转那一遍、两页之间不会出现撕裂；
- 拉伸是非等比的（126 → 240，208 → 320），地图会略微变形——示意性的世界可以接受，
  照片不行；
- 一次失效覆盖 240 × 320 = 76,800 像素，而不是原来的 208 × 126 = 26,208 像素，
  所以这一页的单次重绘成本大约是它来源地图区的三倍。这个数字决定了下面的刷新策略。

## 坑一：`lv_image_set_src` 会重置尺寸与对齐

第一版的现象是地图以原始尺寸画在左上角并被裁掉。原因是顺序：LVGL 9 里设置
src 会重新套用图片自身的尺寸与内部对齐，先设尺寸和对齐、后设 src，等于把前两步
悄悄撤销。

```c
mapfull_dsc_init();                                   /* 先设 src */
lv_obj_set_pos(img, 0, 0);
lv_obj_set_size(img, SCR_W, SCR_H);
lv_image_set_inner_align(img, LV_IMAGE_ALIGN_STRETCH);
lv_image_set_antialias(img, false);
```

接口名字里没有任何暗示它会顺带改兄弟属性；而现象（图片按 1:1 画在角落）看起来
像布局 bug，不像顺序 bug。

## 坑二：整屏图片上叠动画浮层会把板子冻住

舆图页一开始照其他四页的样子做：一个背景盒加本页的装饰。而这一页的装饰是共享的
——事件横幅、星幕、奇观揭示——它们都在内容之上做动画。

现象不是崩溃，也不是看门狗复位：进入这一页后按键不再响应，只能重启。第一反应是
怀疑模拟线程，实际是合成器：每一帧横幅或星幕的动画都会让一大片区域失效，而这片
区域现在压在一张整屏拉伸图上，于是 UI 任务每帧要重新合成大半个屏幕；再加上这一页
当时跟着世界地图四赫兹刷新，自己又叠了一次整屏失效。在没有 PSRAM、没有 GPU 的
板子上，这足以把 UI 任务负责的其他事情全部饿死。

修法是一条规则而不是一个常数：**纯展示页不挂任何会动的装饰。**

- 这一页在前台时屏蔽所有浮层：
  `if (best_t && s_page_idx != 4 && ...) overlay_show(...)`，星幕与奇观揭示同理。
- 任何**需要回应**的东西——祈愿、统治者诏令、人物卡、唤醒报告——先切回世界页再弹：
  `if (s_page_idx == 4) set_page(0);`。弹窗永远不浮在地图上，于是「纯展示」是结构
  保证，而不是靠自觉维持。
- 这一页自己的说明行直接隐藏，而不是写一句别的页都没说的话。

## 一秒刷新一次，并且不要失效底下那页

浮层去掉之后这一页仍然每秒刷新四次，因为它跟世界地图共用更新路径。而地图根本没有
那么快：族群移动以「跳」为尺度，1× 下一跳是 600 ms。

```c
static void refresh_map_full(void) {
    uint32_t now = lv_tick_get();
    if (s_full_ms && (uint32_t)(now - s_full_ms) < 1000) return;   /* 1 Hz */
    s_full_ms = now;
    s_map_rot = true;
    s_map_no_invalidate = true;    /* 不要失效被盖住的世界地图 */
    redraw_map();
    s_map_no_invalidate = false;
    s_map_rot = false;
    lv_obj_invalidate(s_mapfull_img);
}
```

两笔独立的节省：重绘最多每秒一次；重绘缓冲时不再去失效那块藏在地图页后面的世界
地图对象。没有第二个标志位，渲染器每次重绘仍会走一遍那个隐藏的整尺寸对象。

## 可以带走的东西

1. **用索引旋转，而不是旋转像素。** 一块缓冲、一次描述调用、没有旋转那一遍——
   前提是非等比拉伸可以接受。
2. **先设图片 src，再设尺寸与对齐。** LVGL 9 在换源时会重新套用图片属性；由此产生
   的错位看起来像是别处的 bug。
3. **整屏图片页不要挂动画装饰。** 在无 PSRAM 的板子上，浮层的合成成本就是整块屏，
   而且是每帧。让页面结构上就是纯的，并把所有模态内容送回一个能承载它的页面。
4. **按「失效像素」而不是「对象个数」给页面算成本。** 每次刷新 76,800 像素，才是
   决定四赫兹能不能用的那个数——这里不能用。
5. **按键还活着但界面冻住，是时序问题不是逻辑问题。** 切页后不再响应却不重启，
   先看 UI 任务被要求重绘什么，再去看模拟。
