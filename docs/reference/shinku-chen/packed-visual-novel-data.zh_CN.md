# 把视觉小说打包成一块内存映射的数据块

来自 **《沙耶之歌》阅读器**发布。把「剧本 + 美术」内容移植到 AI Passport 的通用做法，
不是 fork 私有定制。

> **验证状态。** 数字来自本次发布的构建与实机：提交进仓库的资源包 2.78 MB
> （44 章、473 场景、3,828 段对白、193 张背景、75 张立绘），一张 320 × 150 背景在
> ESP32-C3 上解码 75–105 ms，实机读通了全部剧本。

## 一块小端数据 + 直接从 Flash 读

把解析工作全部放到主机侧做完，设备侧只当作从应用分区内存映射出来的一段内存来读。可用的布局：

```text
头部    magic、版本、总长、区段数、区段表
区段    { type u32, offset u32, count u32, size u32 }
  TEXT    一整块 UTF-8；每个字符串用 (offset, length) 寻址
  NAME    说话人 / 选项 / 结局名表
  CHAPTER id、首场景、场景数、首对白、对白数、下一章
  SCENE   背景、选项数、首对白、对白数、2 个选项目标
  DLG     文本 offset+len、名字、立绘、flags、jump、参数
  BG      { offset, length, width, height } + JPEG 字节
  FG      { jpeg offset/len, mask offset/len, width, height } + 字节
  META    key=value 的来源信息
```

区段内的 offset 相对该区段自身的数据区，加载器因此只需要几次指针加法；设备端没有 JSON 解析、
没有解压、没有逐帧分配。

## 在打包期清理剧本，而不是运行期

来自别的引擎的剧本里混着"不是正文"的指令。本移植的剧本里有 31 处音效标签
（形如 `<se id="1" src="…" mode="normal" loop="off">`）；移植版没有音频资源，
在打包器剥离它们之前，这些标签会当成正文显示在对话框里。让文本保持干净的几条规则：

- 打包时剥掉引擎自己的指令（音效、背景、特效标签），并打印剥掉的数量，这样回归在构建输出里可见。
- 用 NFKC 归一 CJK 兼容汉字区（U+F900–U+FAFF）：它们只是标准码位的字形变体，白占子集条目。
- 删掉 C0 控制字符，但保留 `\n` 与剧本用于缩进的全角空格。
- **带控制标志的空文本不要过滤**：本数据里有 3 条空文本携带结局跳转，按"空文本"清理会把三个结局全部破坏。

## 在主机侧预裁美术，设备端只解码与合成

- 背景在主机侧按画面区（此处 320 × 150）做 cover 裁切并存成 JPEG，设备端不做任何缩放或裁剪。
- 立绘按屏幕高度缩放一次、裁到可见带，存成 JPEG + 1bpp 按行打包的遮罩（`stride = (w + 7) / 8`），
  设备端按遮罩合成。立绘只保留可见高度，是让 180 px 宽的立绘塞进无 PSRAM 解码缓冲的关键。
- 惰性解码：本阅读器只在（背景, 立绘）真正变化时才解码一次，所以 160 MHz 的芯片上
  每次 75–105 ms 是可以接受的。

## 让资源包可追溯、可复现

- 把来源信息写进包本身（源仓库、commit、转换器版本、几何与 JPEG 质量参数）。
  成本为零，却能回答"这个文件由哪些输入产生"，不必额外保存构建笔记。
- 内容许可允许再分发时，把生成的包提交进仓库，这样 `git clone` 就能构建出可玩固件；
  重新生成只需上游内容 checkout。在素材文档里记录重新生成命令。
- 把资源包当成有 schema 的数据：一个宿主机测试打开提交进仓库的包、校验所有计数/偏移/遮罩长度，
  就能在不刷机的情况下抓住打包器回归。
