# 三键输入语义：只有单击与长按才算用户意图

在发布 **亚托莉阅读器** 之后整理：这个三键阅读器的「长按下开关自动阅读」在开启的瞬间就把
自己关掉了。

## 抬起事件不是按键

按键组件会上报 PRESS / RELEASE / CLICK / LONG 四种事件。第一版在**任意**事件上都取消自动
阅读模式，于是"开启它"的那次长按紧跟着收到了自己的抬起事件，模式当场死掉。开关、处理函数、
长按判定都是对的 —— 错的是"哪些事件算用户意图"。

值得保留的规则：

- 只有 **CLICK** 与 **LONG** 表示「用户下达了指令」。RELEASE 只表示"键不再被按住"，永远不
  当作命令。
- RELEASE 只有一个用途：结束"按住持续生效"的行为（这里是快进）。页面切换时也要把它停掉，
  否则一次残留的按住会在画面已经往前走之后继续推进。
- 由长按触发的模式开关，必须忽略紧随其后的那次抬起。

## 按键时序属于契约的一部分

- **短按阈值 120ms**：触点会抖动，极短的接触不应该被当成一次指令。
- **长按 300ms**：这个时长既像"有意按住"，又不失即时感。某些移植用 1 秒来表达同一个手势，
  会让阅读类操作显得迟钝；如果长按是主要操作而不是菜单快捷键，就应该缩短它。
- "按住重复"（快进）属于应用自己的 tick，而不是按键驱动：驱动只上报边沿，重复速率与何时
  停止由应用决定。

## 回调纪律

按键回调跑在厂商组件的共享 `esp_timer` 任务里。把事件入队后立刻返回：不要在那里拿 LVGL 锁、
不要碰存储、不要启动音频。应用自己的输入任务负责排空队列、每轮处理一个事件，并且只取一次
LVGL 锁。

## 区分"活动"与"等待"

空闲计时（调暗、熄屏、深睡）在任何真实按键事件上归零。无人值守的自动推进模式必须算作活动，
否则长时间无人看管会在读到一半时黑屏；但"停在某个决策点等玩家"不能算活动，否则需要输入的那
一屏永远不会睡。请把它写成一条明确的判定（模式开启 **且** 正在推进），而不是让整屏豁免。
