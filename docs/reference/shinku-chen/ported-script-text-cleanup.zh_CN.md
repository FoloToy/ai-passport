# 移植剧本进入阅读器之前要先清洗

本条目来自 **limelight lemonade jam 阅读器**（`v0.1.0-limelight`）。它的上游数据是商业剧本
的二次编辑版：68,229 句里有 **111 句**混着不是对白的内容——按普通文字渲染出来，看起来像剧情
乱了，而不是像排版问题。清洗放在打包器里做，阅读器和固件都见不到原文。

## 数据里有什么

- **内联排版指令（104 句）**：`%f` / `%r` 切换与重置字体、`$名字$`（也有没有收尾标记的
  `$名字`）插入一张命名图片、`#rrggbbaa` 设颜色——例如
  `「来，射出来吧%f$ハート$#00ffadd6♥%r快点」`。要删的是指令本身，夹在中间的可见 `♥` 是正文。
- **混进正文的译者备注（7 句）**：`memo:` 后面跟着日文原文与英文说明，有三种写法
  （`memo:`、`memo :`、`memo「:」`）。最长的一条 740 字节，分页后是六屏英文说明挤在对话框里。

## 真正管用的几条规则

- **只在打包器里清洗，不在阅读器里清洗。** 阅读器只看到 UTF-8 正文，规则可以在宿主机上测，
  固件零开销。
- **先匹配成对写法，再匹配单个写法。** `$名字$` 与 `$名字` 需要两条规则，而且成对的优先：
  否则 `$ハート$#00ffadd6` 会留下一个孤立的 `$`。
- **不能吃掉正常标点。** 第一版用 `\$[^\s]{1,16}` 时把 `价格 $5 的琴弦` 里的 `$5` 也吃掉了——
  等于**悄悄改了正文**。改成要求名字以字母/假名/汉字开头
  （`\$(?=[^\W\d_])[^\W\d_]{2,16}`）就对了，这个用例现在是一条回归测试。
- **清完要自检。** 清洗后再扫一遍"还像指令"的形状（`$` + 字母、`#rrggbb`、`%` + 字母）并计数；
  将来出现新写法时，会在打包报告里变成一个数字，而不是等到截图里才发现。

## 清洗前后的差别

| | 清洗前 | 清洗后 |
| --- | --- | --- |
| 需要翻页的对白 | 20 句 | 13 句 |
| 单句最多页数 | 6 页 | 2 页 |
| 最长一句 | 740 字节 | 240 字节 |

为了找同类残留，还扫了一遍"英文字母占比 ≥ 60%"的句子：剩下 5 条都是正当内容——一个 Livehouse
名字、一个 "OK"、一个乐队名，以及两句罗马字拟声词。

## 适用范围

任何"被人工翻译、排版或编辑过"的移植数据集都可能带这类残留，而阅读器无法把它和对白区分开。
给整份剧本留一次通扫的预算：统计标记数量、找类似备注的前缀，并为清洗规则产生的每个误报留一条
回归测试。
