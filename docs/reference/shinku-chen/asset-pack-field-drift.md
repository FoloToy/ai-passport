# Asset Packs: Make a Field Drift Fail Loudly

Captured while releasing the *Starry Sky Railroad and Shiro's Journey* reader.
The application reads its script, backgrounds and sprites from one binary pack
generated by a Python packer; the C side parses fixed offsets. When a field was
added to one record type, the packer wrote it and the reader never read it. Nothing
crashed, the build stayed green, the host tests passed — and the product behaved
wrongly in a way that looked plausible for weeks. This entry is the post-mortem and
the three habits that would have caught it.

## What happened

- The sprite record (`SEC_FG`) grew from 24 to 26 bytes: `color_offset`, `color_len`,
  `mask_offset`, `mask_len` (four `uint32`), then `w`, `h`, `x`, `y`, `owner` (five
  `uint16`). The packer wrote the owner — the character a sprite belongs to, derived
  from which named speaker references it.
- The C reader parsed up to `y` (offset 22) and returned. `owner` stayed zero from
  the `memset` at the top of the function, silently meaning "name table index 0".
- The UI rule is "a sprite appears only while its owner character speaks". With every
  sprite owned by index 0, the rule degenerated into "a sprite appears only while
  the protagonist speaks" — 1,005 of 11,777 dialogue steps instead of 3,444, and
  never for the other six characters. It looked like an over-strict rule, not a bug.

## Why the tests did not catch it

- The host test asserted a **count** — `sprite_steps > 800` — and 1,005 passed. The
  threshold had been calibrated against the buggy behavior.
- It also asserted "the owner of a drawn sprite equals the speaker", which is
  trivially true when every owner is the same index.
- The Python-side test parsed the pack file and verified the owner field was present
  and in range. It checked the **producer**, not the **consumer**.
- No test compared what the two sides see for the same record.

## Habits that catch this class of bug

1. **Assert on a distribution, not a count.** "The drawn sprites must cover at least
   five distinct owners" fails loudly on the drifted reader (one owner) and passes on
   the fixed one (seven). Counts measure how much happens; distributions measure
   whether the data still carries its variety.
2. **Cross-dump one real record from both sides.** A five-line script that prints the
   parsed fields of record *n* (Python) and the same fields after the C reader parses
   the same bytes pinpoints drift in seconds. Cheap to keep, and it also catches
   layout mistakes the file-level test cannot see.
3. **Let the producer assert the invariant too.** The packer knows the reference
   statistics; it can fail the build when the data degenerates ("more than half the
   sprites share one owner") instead of leaving a runtime rule to do it silently.

Keep one offset table as the single source of truth (the record size constant lives
next to the packer's format string, and the reader documents the offsets in the same
order), and re-read the parser whenever a field is appended — appending is the change
that compilers and format checks cannot see.
