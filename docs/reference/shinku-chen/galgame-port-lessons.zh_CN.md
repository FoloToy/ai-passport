# Galgame 阅读器移植经验

AI Passport 上用同一套阅读器框架移植了十二部视觉小说：*anemoi*、*Steins;Gate*、
命运石之门0（*Steins;Gate 0*）、*CLANNAD*、*Summer Pockets REFLECTION BLUE*、《魔法少女的魔女审判》、
*PARQUET*、《娘々恋爱故事》*（NianNiang Love Story）*、*《想成为Galgame领域大神！！！》*、
*eden\**、星之终途（*Stella of the End*）、纸上的魔法使（*Paper no Mahou Tsukai*）。本文记录它们共同的需求、框架提供的能力、
只在真机上才暴露的缺陷，以及发版前的验收清单。它是写给下一个移植看的，不是更新日志。

设备是 ESP32-C3，8 MB Flash，**没有 PSRAM**。下面所有约束都由此而来。

## 需求

**三个键，每个键只有一个含义。** 设备只有 UP / DOWN / OK，所以每部作品的语义必须一致：

- OK 短按推进一页；如果这一页还在打字，短按是「立刻显示整页」，而不是跳过。
- OK 长按打开菜单。所有二级页（菜单、存档、设置、历史、鉴赏、章节、关于、CG 浏览）
  都必须能退出，OK 长按是通用的「返回」。
- UP 长按按住期间快进，松手停止。
- DOWN 长按开关自动阅读。
- 列表和选项里，UP/DOWN 短按移动光标，OK 短按确认。

**对话框。** 面板贴屏幕底边、占满宽度、半透明（美术要能透出来）。正文从面板顶边下 4 px 开始，
说话人名字在面板上沿之外，页码放在面板之外（或独立窄条里），绝不压正文。

**正文宽度。** 正文按固定像素宽度排版，再按字号换算的「单位数」分页：全角字 2 单位、
半角 1 单位。每行必须留一个字的余量，否则行首禁则标点「挂」到行尾会让这一行多折一行，
最后一行被裁掉。

**空闲策略。** 无操作时 60 s 调暗背光（*summer* 与 *galgod* 首批页面较长，用 90 s），
300 s 熄屏，1800 s 进深睡；任意按键唤醒。自动阅读与快进**不算**空闲：
无人值守跑自动阅读时屏幕必须保持常亮。

## 能力

- **打包内容。** 剧本、图像、字库打包成一到两个二进制 blob 内嵌到应用资产分区，
  clone 下来就能构建出完整可玩的固件，不依赖网络和 SD 卡。
- **按需解码。** 只解码当前页需要的那张图，解到屏幕大小的画布上；JPEG 走 ROM 解码器，
  立绘与叠加层用无损 RGB565 加 1 bpp 遮罩。
- **分带渲染。** 一整块 320x240 RGB565 画布是 153,600 B，而真机最大连续堆块通常只有
  8–30 KB，所以美术按水平分带绘制：每条带直接解码进自己的缓冲，内存不随屏幕尺寸增长。
- **快进瞬显。** 快进是「整页立刻出现」，不是把打字机调快；自动阅读保留打字机，
  整页打完后等待再翻页。
- **标准页面。** 存/读档（多个手动槽 + 一个自动槽）、鉴赏室（CG 解锁）、章节列表、
  历史（可滚动、换行）、设置（打字速度、字号、面板透明度、空闲行为）、关于页。
- **共享阅读层。** 多数作品复用 `main/gal/` 的阅读层，只增加自己的包格式与美术管线；
  *galgod* 与 *manosaba* 在 `main/` 下自带一套阅读/UI 层。

## 踩过的坑

每条都是「现象 → 根因 → 修法」。全部在真机上发现，宿主测试都没拦住。

### 1. 单行文本折行，或者干脆整条消失

**现象。** 列表行或说话人名字折成两行；或者名字框明明是空的，但字符串确实设进去了。

**根因。** LVGL 9 里 `LV_LABEL_LONG_DOT` 是**多行 + 省略号**：先折行再给最后一行加省略号；
单行版本是 `LV_LABEL_LONG_MODE_DOTS`。而把 `LV_LABEL_LONG_MODE_CLIP` 和
`LV_SIZE_CONTENT` 一起用来定宽，布局会算出宽度 0 —— 对象存在、文本也在，但什么都不显示。

**修法。** 需要单行省略号的用 `LV_LABEL_LONG_MODE_DOTS`；只有历史页用 `LV_LABEL_LONG_WRAP`；
被裁的单行必须给明确宽度（可用宽度减数值列）。**绝不**把 `CLIP` 和 `LV_SIZE_CONTENT` 配对。

### 2. 颜色红蓝互换：人脸发青，红色为主的图发紫

**现象。** 肤色发青、以红色为主的背景发紫；红色少的图看着几乎正常。

**根因。** tjpgd 用 `JD_FORMAT 0` 时输出是 **B, G, R**，不是 R, G, B。把这些字节直接拼成
RGB565 就红蓝互换。损坏程度取决于画面里红色多少 —— 这也是「只有部分 CG 发紫」的原因。

**修法。** 写画布时换序（`bgr_to_rgb565()`），或把解码器输出改成 RGB。一直是换序的移植看不出来，
这个 bug 就被掩盖很久。

### 3. 设置图像之后整屏变黑

**现象。** 本该显示背景的页面变黑，之后翻页也一直是黑的。

**根因。** `lv_image_set_src()` 会把对象尺寸重置成内容尺寸。描述符不被识别时（magic 不对、
颜色格式不对、stride 为 0）内容尺寸是 0x0，对象就塌成 0。

**修法。** 先 set_src，再显式 set_size 到美术区尺寸；交给 LVGL 之前校验描述符头
（magic、颜色格式、宽、高、stride）。

### 4. 右边缘出现一条半透明竖线

**现象。** 美术区右边多出一条像滚动条的半透明竖线。

**根因。** 组成画面的分带都是 root 的子对象，带高之和超过屏幕高（例如 6 x 56 = 336 > 320）时，
root 变成可滚动，LVGL 就画出滚动条。

**修法。** 给 root 清掉 `LV_OBJ_FLAG_SCROLLABLE`，并把最后一条带的高度裁到正好贴满屏幕。

### 5. 同一张图重复显示三份

**现象。** 本来一张背景，屏幕上变成同一张图横向重复三段。

**根因。** 所有分带共用一块像素缓冲和一个图像描述符，于是所有描述符都指向最后写入的那一块，
每条带显示的都是最后一次写入的内容。

**修法。** 每条带**各自一块缓冲 + 各自一个描述符**，启动时绑定到自己的 `lv_image` 对象，之后不再改。

### 6. 大画布在真机上申请不到

**现象。** `heap_caps_malloc(153600)` 在真机返回 NULL，而宿主测试通过；退化成「整幅缩放」又会出现
黑块或丢一条带。

**根因。** 堆总量约 187 KB，但最大连续块常只有 8–30 KB —— Wi-Fi/蓝牙栈、LVGL 池和任务栈
把 DRAM 打碎了。

**修法。** 分带绘制，带高按实测最大连续块来定（例如 4 x 80 或 5 x 64 行），从大到小探测并
留显式回退与日志。**不要**设计任何需要 >32 KB 单次分配的路径。

### 7. 横竖屏切换卡死或白屏

**现象。** 开机切方向时卡住，或者第一帧是白的。

**根因。** `lv_display_set_rotation()`（以及 BSP 的横屏封装）会动 LVGL 状态和面板，
不持 LVGL 锁就调用会与 LVGL 任务竞争。

**修法。** 调用前后持 `bsp_lvgl_lock()`（后续布局工作也一起放在锁内）。方向是开机决策，
不做运行时热切换。

### 8. 输入任务报 `Stack protection fault`

**现象。** 翻几页后 panic：`Stack protection fault, Detected in task "xxx_input"`。

**根因。** 输入任务里直接调了 LVGL 刷新与渲染，而它的栈只有 4096 字节。

**修法。** 输入任务栈提到 8192，或者把重活挪进 LVGL 任务、输入任务只负责入队事件。

### 9. 长按 OK 之后下一个 OK 没反应，或者菜单多走一步

**现象。** 长按 OK 进菜单，菜单立刻往下跳一行；或者反过来，列表里第一次短 OK 没反应，
选项「选不了」。

**根因。** 长按松手时驱动会补发一个 CLICK。无脑吞掉所有 CLICK 解决第一个现象，
却造成第二个：标志一直挂着，把真正的那次按键吃掉了。

**修法。** 只在**限时窗口**内吞（长按后约 400 ms），并在 PRESS 时清标志（新手势总是干净的），
窗口过期也清掉。

### 10. 读到某个字符串就卡死（看门狗复位）

**现象。** 进某个页面触发看门狗复位且没有 panic 信息；同样的页面在宿主测试正常。

**根因。** 包里字符串是「长度前缀 + 非 NUL 结尾」，把这种指针直接交给 `lv_label_set_text()`
会让 LVGL 一路扫 Flash，直到碰巧遇到 0。

**修法。** 校验长度在包边界内，拷进有界缓冲并补 NUL，再交给 LVGL。

### 11. 源码已提交，版本号却还是 `<hash>-dirty`

**现象。** `esp_app_desc.version` 是 git describe 字符串，不是发布版本号。

**根因。** ESP-IDF 在 `project()` **之前**就读取 `PROJECT_VER`；写在 `project()` 之后的
`set(PROJECT_VER "1.0.0")` 会被忽略，构建退回 `git describe`。

**修法。** 把 `PROJECT_VER` 放在 `include($ENV{IDF_PATH}/tools/cmake/project.cmake)` 之前，
并且要直接读构建产物里的 `esp_app_desc` 校验，而不是只看 `project_description.json`。

### 12. 立绘悬空，或者同一个角色出现三份

**现象。** 全身立绘离对话框上沿留了 20–30 px 空隙；或者一个角色并排画了三份。

**根因。** 基线用了原图像素高，而解码器返回的是缩放后的高；另外包里同一角色按表情占多个槽位，
有时三个槽位指向三个不同 id 但内容是同一份 JPEG，按 id 去重拦不住。

**修法。** 用**解码后实际高度**算基线（`y = panel_top - h`）；同帧内按内容去重：
宽高相同且 JPEG 长度相差 ≤160 B 视为同一具身体，只保留最后一个槽位。

## 验收清单

发版打 tag 之前，在真机上走一遍。

- 开机直接进标题页，没有测试菜单、不联网。
- 字库子集覆盖完整，没有缺字；第一章每一行都能读出来。
- 美术正确：背景、立绘基线、CG 颜色顺序，没有黑块、没有重复分带。
- 方向与作品一致（320x240 或 240x320），没有翻转。
- OK 短按推进、OK 长按开菜单、UP 长按快进、DOWN 长按自动；长按之后不会多走一步。
- 每个二级页都能用 OK 长按退出，包括列表最后一页和关于页。
- 存/读档、鉴赏、章节、历史都正常，读档回到同一句。
- 快进连续推进、没有逐行停顿；自动阅读保持常亮，遇到选项停下。
- 空闲：60 s 调暗（配置 90 s 的作品按 90 s）、300 s 熄屏、1800 s 深睡，按键唤醒后回到原进度。
- 完整读一章不出现 panic、看门狗复位、`Stack protection fault`。
- 构建产物里的 `esp_app_desc` 是发布版本号，不是 git describe 字符串。
