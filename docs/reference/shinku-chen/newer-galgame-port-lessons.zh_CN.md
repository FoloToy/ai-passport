# 新一代 Galgame 批量移植经验

2026 年下半年移植并发布八部作品时整理：天使☆騒々 RE-BOOT!、死馆、星光咖啡馆与死神之蝶、
爱上火车·二六线，以及 9-nine 四部曲。这里只保留跨作品成立的规则；单部作品的预算与
特殊取舍留在各自的 application playbook 里。

## 以手环移植工程为事实源

- 八部移植都来自 `xuanyide01/*-rw5` 的处理后工程，并固定在确切提交上。转换后的
  graph、engine 与 chunk codec 是权威；不要重建未提交的 PC 原作脚本。
- 源图里不可达的节点与条件要保持不可达。某个闸门在原作里永远不会触发，就不要为了
  让移植看起来“完整”而虚构一条路线。
- 9-nine 四部共用同一个上游工程与同一套阅读器，但各自独立出固件；复用阅读器，
  不复用内容包。

## 阅读器契约保持一致

- 三个短按键都立即推进。打字中或自动播放中按下也推进，不能只补全文字或退出自动
  并把这次按键吞掉。
- 长按只执行长按动作；松手不再额外触发一次短按推进。
- 长按 UP 按整句快进，跳过打字与自动等待，在选项、结局与 OP 处停住，绝不替读者
  选择。
- 长按 DOWN 开关自动播放；自动播放中按短键会退出自动并在同一次按键里推进。
- 从菜单、存读档、设置或历史返回时，回到同一文本页；从选项页返回时恢复完整选项
  列表与光标。
- 章节预览与鉴赏室播放不写自动进度或永久进度，也不解锁结局或 CG。

## 显示按条带算，不按整帧算

- 常见布局是 320×180 舞台 + 60 px 对话框。源图是 432×243，保留 16:9 构图，
  不要为了填满对话框而裁切。
- 星光咖啡馆把舞台按 224×126 打包，运行期画三条 224×42 RGB565 条带，再由 LVGL
  缩放到 320×180。立绘与表情用 2 bpp alpha 遮罩（4 级）；JPEG 段去重与帧画缓存
  避免重复美术进入堆。
- TSXX 用 150 KB RGB565 画布，不配解码暂存：tjpgd 回调直接写画布，立绘用 1bpp
  遮罩，脚本区间常驻只读映射，图片走 256 KB 滑动 `esp_partition_mmap`。
- 九次九日九重色把 320×180 舞台内部按 256×144 解码，再以 1.25× 显示。
- 选布局前先测最大连续堆块。无 PSRAM 的板子上，整帧 RGB565 加解码暂存通常不是
  正确答案。

## 运行状态与永久进度分离

- 存档记录保存节点、帧索引、文本页与当前周目变量，使用稀疏、CRC32 校验、绑定
  资源包身份的记录。九次九日九重色有 30 个手动位；爱上火车、死馆与天色各有 3 个。
- 永久 key 放在独立 NVS 记录。读档、回退、章节预览或鉴赏室播放都不能把已完成的
  结局回滚。
- 损坏的存档或进度记录要在屏幕上提示，不能静默应用；当前运行状态保留。
- 章节或 CG 预览是隔离的运行。即使从第 1 章在预览里读到结尾，也不授予结局；只有
  「开始游戏」的正式周目才算。

## 音频与 OP 视频

- 4 / 8 / 12 kHz 的 IMA ADPCM 在播放时插值到 16 kHz，可以把完整标题曲与 OP 放进
  Flash，而不必用方波替代。爱上火车保留了完整的 283.88 秒标题曲。
- OP 视频降帧而不删剧情内容：九次九日九重色把 599 帧 @6fps 降到 300 帧 @3fps；
  天色保留 623 帧 @5fps；春色保留 493 帧 @5fps；星光咖啡馆把 5fps 源保留为
  287 帧 224×126 q15 @3fps。
- OP 复用已有的条带与舞台，不为视频再分配一份整帧 RGB565。
- 鉴赏室播放独立于正在运行的剧情 VM：不推进 VM、不写存档、不解锁结局与 CG。

## 能抓住移植回归的验证

- 把每一帧对白、选项目标、条件与结局引用与源 graph 对账。春色对账了 10,659 帧，
  并用 10,674 步轨迹与源 `engine.js` 完全匹配。
- host 测试覆盖资源包解码、合成采样、三键状态机与存档 / 进度格式。真实 LVGL
  解码与 32 位 / 64 位 UI smoke 能抓到纯数据测试漏掉的布局与分配器问题。
- 设备结果与 host 结果分开报。长跑掉电、完整路线真机运行与音频质量都需要独立
  证据；不要把构建通过写成设备验证通过。

## 该复制与不该复制的东西

- 复制：源固定方法、阅读器契约、试读隔离、分带显示预算、源 graph 对账。
- 不要复制：某部作品的条带数、存档位数量或帧率；要先测量。可复用的是预算方法，
  不是具体数字。
