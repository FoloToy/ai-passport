# 共用解块缓冲只能有一个所有者

一个阅读器往往要解好几路数据（页表、正文流、图片行块），在没有 PSRAM 的板子上只能共用
一块解块缓冲。坑出在「每路各自记缓存」：页表查到过一次第 7 块，接着正文流把第 3 块解进
同一块缓冲，下一次页表查询就命中"过期缓存"，拿到的其实是正文数据。

## 症状

单页看起来完全正常：跳到某页、渲染，图对、字也对。只有**连续读**才会暴露：从第二页起
记录解出来是乱的，正文切片也定位不到，而"加载失败 == 没有更多内容"的写法会把它当成剧情
结束，直接退回标题页。玩家的描述是"章节接不上""读两行就弹回去" —— 听起来像剧本数据的问题，
不像缓冲的问题。

这也是**单帧截图流水线**（跳到第 N 页 → 抓图）抓不到它的原因：每次抓图都从冷缓存或自洽
状态开始。连续性缺陷必须用"会前进"的验证：连续注入按键推进，或在宿主机上按同一套规则把
页面图走一遍。

## 修法

把共用缓冲变成"同一时刻只有一个所有者"：每次解块时，除了记下自己这一路，还要把**另一路**
的缓存作废，而不只是更新自己的。

```c
int32_t *cache = is_page ? &scn->cached_page_block : &scn->cached_text_block;
int32_t *other = is_page ? &scn->cached_text_block : &scn->cached_page_block;
if (*cache == (int32_t)index) return scn->scratch;
/* ... 解压进 scn->scratch ... */
*cache = (int32_t)index;
*other = -1;   /* 这次解压把另一路的数据冲掉了 */
```

配套两条规则能挡住同一类问题：

- 调用方要把「解压失败」和「流的内容结束」当成两种结果。把两者都归到"没有更多内容"，
  就会让缓冲缺陷伪装成正常结局，日志里也看不出来。
- 启动自检打印第一块解压后的字节数与首句。把"一进阅读就退出"变成一行诊断信息。

## 背景

这是在把《DRACU-RIOT!》移植到 AI Passport（ESP32-C3、无 PSRAM）时发现的：一块 4 KB
解块缓冲同时服务剧本页表和正文流。任何「多路块流 + 一块共用缓冲」的包格式都会碰到同一
个坑；周边管线见该应用的归档页。
