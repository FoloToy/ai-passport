# Claude Desktop Buddy 移植设计

## 目标

将 Anthropic `claude-desktop-buddy` 的核心体验原生移植到 FoloToy-Card。固件基于 ESP-IDF 5.5.3 和现有 BSP，启动后直接进入 Claude Buddy，不再保留当前硬件演示菜单和 `demo_*` 业务逻辑。

移植采用分阶段交付：第一阶段完成安全 BLE 连接、Claude 状态与审批交互、单个 ASCII Buddy、设置与基础统计；第二阶段再加入完整角色集、GIF 角色包、文件系统和 BLE 文件推送。

## 硬件与平台约束

- MCU：ESP32-C3，无 PSRAM。
- 屏幕：ST7789P3，240 × 320 竖屏，使用 LVGL。
- 输入：三个 ADC 按键 `UP`、`DOWN`、`OK`。
- 可复用外设：显示、按键、电池、音频和共享 I2C BSP。
- 目标框架：ESP-IDF 5.5.3，不引入 Arduino 或 M5StickCPlus 兼容层。
- 目标板没有 IMU，因此不实现摇晃触发眩晕和翻面睡眠。

## 范围

### 第一阶段

- Nordic UART Service BLE 外设和自动重连。
- LE Secure Connections、绑定、六位配对码显示和设备端取消配对。
- 换行分隔 JSON 协议、心跳快照、状态响应、时间和 owner/name 命令。
- Claude 会话状态、近期消息、Token 统计和工具审批展示。
- 在设备上批准一次或拒绝权限请求。
- 单个 ASCII Buddy 和状态动画。
- Buddy、最近消息、设备状态、设置及配对页面。
- NVS 设置与基础统计。
- 主机侧协议/状态机测试和设备侧验收。

### 第二阶段

- 上游完整 ASCII 角色集和角色切换。
- GIF 解码与渲染。
- LittleFS 角色包存储。
- `char_begin`、`file`、`chunk`、`file_end`、`char_end` 文件传输。
- 路径校验、容量控制、中断清理和传输恢复策略。

第一阶段收到文件传输命令时返回明确的“不支持”错误，不创建半成品文件。

## 架构

保留 `components/bsp` 作为唯一板级硬件层。删除 `main/demo_*.c`、旧菜单和旧 UI 调度逻辑；可复用的纯逻辑工具只有在新实现确实需要时才保留。

应用由以下边界清晰的模块组成：

1. **BLE 传输层**：注册 NUS 服务、处理连接与安全事件、组装按行消息、分片发送通知。
2. **协议层**：解析有界 JSON 输入，校验字段并生成领域事件；序列化响应、ack 和权限决定。
3. **应用状态机**：维护连接、配对、会话、审批、角色和页面状态，执行超时及安全决策。
4. **LVGL 界面层**：只消费不可变快照和输入事件，不直接依赖 BLE 回调。
5. **持久化层**：通过 NVS 保存设备设置、绑定相关设置和统计，不保存临时对话内容。

BLE 回调不得操作 LVGL。数据流为：BLE 字节流 → 完整 JSON 行 → 协议事件 → 应用状态机 → UI 快照 → LVGL 刷新。按键流为：BSP 按键事件 → 状态机 → 页面动作或协议发送。

角色渲染通过统一接口接收 `sleep`、`idle`、`busy`、`attention`、`celebrate`、`dizzy`、`heart` 状态。第一阶段只有一个文本角色实现；`dizzy` 保留为接口状态但没有本机实体触发，为第二阶段或远端扩展预留兼容性。

## BLE 与安全

设备广播 Nordic UART Service，名称默认为 `Claude-<MAC 后缀>`：

- Service：`6e400001-b5a3-f393-e0a9-e50e24dcca9e`
- RX，桌面到设备：`6e400002-b5a3-f393-e0a9-e50e24dcca9e`
- TX，设备到桌面：`6e400003-b5a3-f393-e0a9-e50e24dcca9e`

RX、TX 和 TX CCCD 要求加密访问。设备使用 LE Secure Connections 绑定和支持显示六位 passkey 的 IO 能力。首次访问受保护特征触发系统配对；配对页显示 passkey，成功后自动返回 Buddy。已绑定主机可自动重连。

取消配对和恢复默认设置必须经过设备端确认。取消配对删除绑定信息并断开当前连接；恢复默认设置同时清除应用设置和统计。状态响应中的 `sec` 仅在当前链路实际加密后为 `true`。

## 协议行为

传输使用 UTF-8 JSON，每个对象以 `\n` 结束。接收层在固定容量缓冲区中累计数据；遇到超长行时丢弃至下一换行并报告协议错误，不能继续扩容。所有字符串字段复制到固定上限的状态结构，超长可显示字段允许安全截断，关键字段如审批 ID 超限则拒绝整条消息。

心跳快照更新：

- 会话总数、运行数和等待数；
- 一行状态摘要；
- 有限条近期记录；
- 累计和当日 Token；
- 可选审批 ID、工具名和参数提示。

30 秒未收到快照时，状态机将连接视为失活，清除当前审批并进入离线/睡眠显示；BLE 链路仍可独立尝试恢复或等待下一条有效快照。

支持以下命令及对应 ack：

- `status`：返回设备名、安全状态、电池、运行时间、可用堆和统计。
- `name`：校验并保存显示名。
- `owner`：校验并保存 owner 名称。
- `unpair`：进入设备端确认流程，确认后执行。
- `time`：更新仅用于显示的时间基准，不依赖它做安全判断。

未知命令返回 `ok:false` 和简短错误。无法解析且没有可靠 `cmd` 的输入只记录错误，不伪造 ack。

## 审批与按键交互

收到包含 `prompt` 的有效心跳时，界面强制切到审批页。审批页显示工具名和参数提示，长内容可滚动：

- `OK` 短按：发送 `{"cmd":"permission","id":"...","decision":"once"}`。
- `DOWN` 短按：发送 `{"cmd":"permission","id":"...","decision":"deny"}`。
- `UP`：滚动查看工具和参数。

批准和拒绝仅对当前完整匹配的审批 ID 有效。发送后立即锁定该审批，避免按键抖动或重复点击再次发送；直到收到不含该审批的新心跳、出现新审批 ID、断开或超时才解锁。发送失败保持安全默认值，不把操作视为已批准，并显示错误状态。

普通状态下，`UP`/`DOWN` 切换或滚动 Buddy、最近消息和设备状态页面。`OK` 长按进入设置。设置首版包含设备信息、BLE 开关、取消配对和恢复默认设置。

## 状态与角色行为

状态优先级从高到低为：配对/确认对话框、待审批、短时庆祝或爱心、忙碌、已连接空闲、离线睡眠。

- `sleep`：没有有效桌面连接或心跳超时。
- `idle`：连接有效且没有运行任务或审批。
- `busy`：至少一个会话正在运行。
- `attention`：存在有效审批请求。
- `celebrate`：达到统计里程碑时短时播放。
- `heart`：审批在五秒内获批时短时播放。
- `dizzy`：接口保留，第一阶段没有触发源。

临时动画结束后重新计算基础状态，不能覆盖新到达的审批。

## 界面设计

240 × 320 主界面布局：

- 顶部状态栏：BLE、加密状态和电池。
- 中部角色区：ASCII Buddy 和轻量逐帧动画。
- 底部信息区：Claude 状态摘要、会话信息和按键提示。

待审批使用高对比卡片并优先占用信息区。配对使用独立页面显示六位码。最近消息页只展示桌面发送的有限条目，不保存或构造完整聊天记录。所有 UI 文案使用英文。

动画使用文本和简单 LVGL 图元，不加入大位图资源。LVGL 对象只在 UI 所在线程创建和更新；UI 从队列或受控快照读取状态，避免跨任务调用 LVGL。

## 持久化

NVS 保存：

- 用户设置的设备名与 owner 名称；
- BLE 开关和必要的应用设置；
- 批准数、拒绝数及其他已实现统计；
- 角色接口所需的默认选择标识。

BLE 控制器的绑定密钥使用 ESP-IDF 提供的持久化机制。近期消息、工具参数、审批 ID 和当前会话计数不写入 Flash。统计更新采用限频或批量提交，避免每次心跳写 Flash。

## 错误处理与资源边界

- JSON 行、字符串、近期记录数量和 TX 消息均设置编译期上限。
- 内存不足、JSON 错误、未知字段、未知命令和发送失败不得导致重启。
- 无效或过期审批 ID 永远不能触发批准。
- BLE 断开和心跳超时会清除敏感临时状态。
- 队列满时优先保留连接、安全和审批事件；可合并或丢弃旧的普通心跳刷新。
- 日志不得输出完整敏感参数或审批 ID，只记录类型、长度和脱敏标识。
- 第一阶段不增加 GIF 缓冲、角色文件系统或文件传输依赖。

具体缓冲区大小在实施计划中根据 ESP-IDF JSON 库、BLE MTU 和现有构建的可用内部 RAM 确定，并通过构建产物与板上堆监控验证。

## 测试与验收

### 主机侧测试

将协议解析和状态迁移保持为无硬件依赖的 C 逻辑，覆盖：

- 完整、分片和连续多行 JSON；
- 异常 JSON、超长行、超长关键字段和未知命令；
- 心跳到各角色状态的映射；
- 30 秒心跳超时和敏感状态清除；
- 审批 ID 匹配、重复按键锁和新审批解锁；
- 临时动画不能覆盖待审批状态；
- status/ack/permission 序列化边界。

### 构建验收

- 在 ESP-IDF 5.5.3 环境执行全新配置和 `idf.py build`。
- 检查编译警告、静态 RAM、Flash 占用和剩余内部堆。
- 不以已有 `build/` 产物代替本次干净构建。

### 板上验收

- Claude Desktop 开发者模式能发现 `Claude-*` 设备。
- 首次连接显示正确配对码，加密成功，重启后自动重连。
- Buddy 正确呈现离线、空闲、忙碌、审批、庆祝和爱心状态。
- 工具审批内容可查看，批准/拒绝命令正确且不会重复发送。
- 普通页面、长按设置、取消配对和恢复默认流程正确。
- 电池和状态响应字段正常。
- 反复连接/断开及持续运行时无持续堆下降或看门狗复位。

## 第二阶段入口条件

只有第一阶段完成干净构建及核心板上验收后才开始 GIF/文件推送。第二阶段设计需明确 LittleFS 分区容量、单帧峰值内存、GIF 缓冲策略、文件名白名单、总容量限制、传输中断后的临时文件清理和角色包原子切换。

## 上游兼容与归属

实现以公开的 Hardware Buddy BLE 协议为兼容目标，原生使用 ESP-IDF API。若复制或改编上游角色画面、代码或资源，必须保留其许可证和归属，并在提交前核对对应文件许可；不复制 M5StickCPlus 硬件适配代码。
